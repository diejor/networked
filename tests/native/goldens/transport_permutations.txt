# The loopback link simulator's delivery orders, recorded from the GDScript arm
# at bfdeaa6, before any of it was native. It is the transport family's Bridge-A
# parity instrument: both arms reproduce this file exactly, or one of them is
# not the other.
#
# A row is `<scenario> <seed> <byte>,<byte>,...`. Every scenario runs on a fresh
# private session with one server and one client, conditions installed on the
# server for every sender, and one physics period fixed at 1000/60 ms. The
# client sends single-byte packets numbered from zero.
#
#   reorder      jitter 4 periods, reorder 1.0. Eight unreliable packets, one
#                poll after each, then ten more polls. The row is the order the
#                bytes FIRST arrive in, so a duplicate cannot move it.
#   clear_flush  latency 11 periods, jitter 4 periods, reorder 1.0. Eight
#                unreliable packets sent with no poll between them, then one
#                poll, then clear_link_conditions. The row is the flush order.
#   mixed        jitter 4 periods, reorder 1.0, duplicate 0.5, loss 0.25.
#                Twelve unreliable packets, one poll after each, then twelve
#                more polls. The row is every byte delivered, in order, so
#                losses shorten it and duplicates repeat a byte.
#
# The three scenarios exist to pin four independent RNG streams. `reorder` and
# `clear_flush` pin jitter and the reorder roll, and they differ in whether the
# session clock advances between sends, which is what decides whether the
# stable sort ever has ties to break. `mixed` is the only one that pins the
# loss and duplicate streams, and it is the only one where a stream drawn one
# time too many shows up as a shifted row rather than as nothing.
