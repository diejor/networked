DebugJoinConfig
===============

**Inherits:** :godot:`Resource`

Editor authored stand in for the join arguments that auto connect a :ref:`MultiplayerTree<class_MultiplayerTree>` in debug builds.

.. rst-class:: classref-introduction-group

Description
-----------

The join intent stays coherent with the server because :ref:`join_args<class_DebugJoinConfig_property_join_args>` holds the very values a live client fills into the form drawn from :ref:`NetwMultiplayer.session_get_join_schema()<class_NetwMultiplayer_method_session_get_join_schema>`. Author one entry per parameter the installed handler declares after its :ref:`NetwParticipant<class_NetwParticipant>`.

::

    # On a debug MultiplayerTree, assign a DebugJoinConfig and the tree hosts
    # straight into the game on play, skipping ConnectBrowser.
    debug_join.username = &"Dev"
    debug_join.join_args = [&"Arena", ^"Player"]

\ The array is copied on the way in and on the way out, so a tree that hosts twice off one config cannot have its second join mutated by whatever the first did with the args.

\ :ref:`MultiplayerTree.debug_join<class_MultiplayerTree_property_debug_join>` is the one place it is read, and only when :godot:`OS.has_feature() <OS#class_OS_method_has_feature>` answers ``true`` for ``"debug"``, so a release build never auto connects.
