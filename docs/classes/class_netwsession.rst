NetwSession
===========

**Inherits:** :godot:`RefCounted`

The players, scenes and signals of a :godot:`Node.multiplayer <Node#class_Node_property_multiplayer>` session.

.. rst-class:: classref-introduction-group

Description
-----------

Reached with :ref:`Netw.session()<class_Netw_method_session>` from any :godot:`Node`. Mostly useful for connecting signals.

::

    var s := Netw.session(self)
    s.entered.connect(on_entered)
    s.exited.connect(on_exited)
    for player: NetwPlayer in s.players:
        scoreboard.add(player)

    func on_exited(reason: NetwSession.ExitReason, detail: String) -> void:
        if reason == NetwSession.KICKED:
            show_message("Kicked: %s" % detail)

\ There is one handle per session, so it is safe to keep it across an await.

Connecting is done as you would normally do with :godot:`SceneMultiplayer`, by assigning :godot:`MultiplayerAPI.multiplayer_peer <MultiplayerAPI#class_MultiplayerAPI_property_multiplayer_peer>`. :ref:`connection<class_NetwSession_property_connection>` finds servers and joins or hosts one, and :ref:`Netw.prepare_join()<class_Netw_method_prepare_join>` names the player who joins.

\ **Moving the server**\ 

\ :ref:`transfer_server()<class_NetwSession_method_transfer_server>` makes another peer the server, and :ref:`server_transferred<class_NetwSession_signal_server_transferred>` reports it on every peer. The session also survives the server leaving when its :godot:`MultiplayerPeer` can promote a client by itself. ENet, WebRTC, Steam and :godot:`OfflineMultiplayerPeer` cannot, so losing the server ends them.

On a peer that can, closing the server's window moves the server. The server calling :ref:`leave()<class_NetwSession_method_leave>` ends every client's session, even on a peer that can promote a client, so a server that wants the game to go on without it moves the server first.

::

    func hand_over(successor: NetwPlayer) -> void:
        if session.transfer_server(successor.peer_id) == OK:
            await session.server_transferred
        await session.leave().wait()

\ **Pausing**\ 

\ :ref:`pause()<class_NetwSession_method_pause>` pauses every peer together. Properties stop syncing until :ref:`unpause()<class_NetwSession_method_unpause>`, and RPCs still arrive. Setting :godot:`SceneTree.paused <SceneTree#class_SceneTree_property_paused>` yourself pauses only that peer's nodes, and the session keeps running. In an online game a pause menu usually leaves the tree running, because a paused peer stops predicting its physics bodies and is corrected on unpause.

::

    func _on_pause_pressed() -> void:
        session.pause("The host paused the game")

    func _on_paused_changed(paused: bool, reason: String) -> void:
        pause_menu.visible = paused
        pause_label.text = reason

.. _class_NetwSession_signal_join_failed:

.. rst-class:: classref-signal

**join_failed**\ (\ code\: :godot:`Error <@GlobalScope#enum_@globalscope_Error>`, reason\: :godot:`String`\ ) :ref:`🔗<class_NetwSession_signal_join_failed>`

This peer's join was refused with ``code`` and the ``reason`` the server gave. :ref:`local_player<class_NetwSession_property_local_player>` stays ``null``. A client refused while connecting closes its peer and never goes online, so neither :ref:`entered<class_NetwSession_signal_entered>` nor :ref:`exited<class_NetwSession_signal_exited>` fires.

Networked refuses with three codes, and any other ``code`` is the one the admission handler or a :ref:`NetwAccountProvider<class_NetwAccountProvider>` returned.

- :godot:`@GlobalScope.ERR_UNCONFIGURED <@GlobalScope#class_@GlobalScope_constant_ERR_UNCONFIGURED>` the two peers are set up differently, such as another build, another Networked version or other :ref:`Netw.configure_join()<class_Netw_method_configure_join>` arguments

- :godot:`@GlobalScope.ERR_TIMEOUT <@GlobalScope#class_@GlobalScope_constant_ERR_TIMEOUT>` the player was not admitted before :ref:`NetwAdmissionConfig.timeout()<class_NetwAdmissionConfig_method_timeout>` or :ref:`NetwMultiplayer.auth_timeout<class_NetwMultiplayer_property_auth_timeout>` passed

- :godot:`@GlobalScope.ERR_ALREADY_IN_USE <@GlobalScope#class_@GlobalScope_constant_ERR_ALREADY_IN_USE>` the account already plays as the server's player

.. _class_NetwSession_signal_server_transferred:

.. rst-class:: classref-signal

**server_transferred**\ (\ successor_was\: :godot:`int`, former_now\: :godot:`int`\ ) :ref:`🔗<class_NetwSession_signal_server_transferred>`

Emitted on every peer once the peer that was ``successor_was`` has become the server at id ``1``, and the old server, if it stayed, has become ``former_now``.

\ ``former_now`` is ``0`` when the old server is gone, and its player leaves after this signal.


.. tabs::

 .. code-tab:: gdscript

    func _ready() -> void:
        Netw.session(self).server_transferred.connect(on_server_transferred)

    func on_server_transferred(successor_was: int, former_now: int) -> void:
        scoreboard.rename(successor_was, 1)
        if former_now != 0:
            scoreboard.rename(1, former_now)

    public override void _Ready()
    {
        Netw.Session(this).ServerTransferred += OnServerTransferred;

    private void OnServerTransferred(long successorWas, long formerNow)
    {
        scoreboard.Rename(successorWas, 1);
        if (formerNow != 0)

.. _class_NetwSession_method_leave:

.. rst-class:: classref-method

:ref:`NetwPromise<class_NetwPromise>` **leave**\ (\ ) :ref:`🔗<class_NetwSession_method_leave>`

Leaves the session. The server saves its entity rows first, and stays online if the database refuses a row. The promise resolves with an :godot:`@GlobalScope.Error <@GlobalScope#enum_@globalscope_Error>` once the peer is down or the save failed. Closing the game window leaves the same way. On a server whose :godot:`MultiplayerPeer` can move the server, closing the window tells no client, so the peer promotes one when it can. A server that saves entities loses unsaved changes when its window closes, so it sets :godot:`SceneTree.auto_accept_quit <SceneTree#class_SceneTree_property_auto_accept_quit>` to ``false`` and quits after :ref:`leave()<class_NetwSession_method_leave>` resolves.

.. _class_NetwSession_method_transfer_server:

.. rst-class:: classref-method

:godot:`Error <@GlobalScope#enum_@globalscope_Error>` **transfer_server**\ (\ peer_id\: :godot:`int`\ ) :ref:`🔗<class_NetwSession_method_transfer_server>`

Asks the :godot:`MultiplayerPeer` to make ``peer_id`` the server and this peer a client under a new id. :ref:`server_transferred<class_NetwSession_signal_server_transferred>` follows on every peer. A peer supports this when it declares a ``server_relabelled`` signal and a ``transfer_server`` method. It emits the signal once :godot:`MultiplayerPeer.get_unique_id() <MultiplayerPeer#class_MultiplayerPeer_method_get_unique_id>` already answers the new id. A peer with only the signal can still promote a client when the server is lost.

::

    extends MultiplayerPeerExtension

    signal server_relabelled(successor_was: int, former_now: int)

    func transfer_server(peer_id: int) -> Error:
        return relay.promote(peer_id)

    func _poll() -> void:
        relay.poll()
        if relay.promoted:
            server_relabelled.emit(relay.successor_was, relay.former_now)

\ When the server moves, players who have left lose their return window, and their kept entities despawn. The new server reads each :ref:`NetwPlayer.account<class_NetwPlayer_property_account>` again from the :ref:`LobbyDirectory<class_LobbyDirectory>` serving the session when it names one, and the old server keeps only its own.

.. code:: text

    Error
    ┠╴ERR_UNAUTHORIZED        called on a client
    ┠╴ERR_UNAVAILABLE         the transport cannot move the server
    ┠╴ERR_INVALID_PARAMETER   peer_id is not a connected client
    ┖╴ERR_BUSY                a database still has writes to settle

\ **Server Only.**
